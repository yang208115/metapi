# 运维监控：从请求结果定位故障

运维首页分别展示用户请求的最终结果和上游尝试记录。一次请求先失败、重试后成功，会贡献一个成功请求和多次上游尝试；无可用通道返回的 503 也进入请求结果统计。

## 怎么看

1. 选择站点、平台与滚动观测窗口。主请求指标、响应分布、故障焦点、站点矩阵和请求明细使用同一范围。
2. 先看“故障焦点”。每条线索展示实际计数、下一步检查方向，以及请求结果、尝试日志或路由管理入口。
3. 查看“数据可信度”。观测开始前的旧日志不会伪装成请求结果；样本缺失、写入失败和历史覆盖不足会明确展示。
4. 点击“定格复盘”暂停轮询。点击时间线中的柱子，可查看该时间片的请求结果。更改筛选或手动刷新会生成新快照。
5. 根据站点矩阵区分用户失败与上游尝试失败。“重试挽回”显示上游尝试失败后仍完整成功的请求，可单独下钻。

## 指标口径

| 指标 | 定义 |
| --- | --- |
| 用户请求 | 当前完成时间范围内记录的最终请求数，包含成功、失败、拒绝、取消和未知结果 |
| 最终成功率 | 完整成功请求数 / 全部已记录请求数；429、529 不从分母中静默扣除；无请求显示 `—` |
| 失败请求 | 明确失败的最终请求数；拒绝、取消与未知另列 |
| 重试挽回 | 发生多次尝试、有失败尝试、最终成功的请求数 |
| 请求总耗时 | 从请求入口到响应结束的时长，包含请求中发生的重试和等待；平均值、P50/P90/P95/最大值仅使用有效样本 |
| 上游首块时延 | 上游响应首个数据块的时延；不等同于首个有效 Token 的时间，不标作 TTFT |
| 短窗口吞吐 | 最近 1/5/30/60 分钟内完成请求数或已记录 Token 数除以窗口秒数；峰值使用固定宽度桶 |
| 站点可选通道 | 按路由、站点、账户、凭证与冷却条件判断的候选通道，不代表刚刚主动探测成功 |
| 业务分析 | 同一站点/平台范围下，独立的 7/30/90 个自然日分析；调用数仍来自历史尝试日志，不能与用户请求总数直接对比 |

请求分配给最终关联的站点；无通道等未关联站点的结果单独保留在全局视图。切换到某个站点或平台后，这类请求不应被强行归属。

## 刷新与数据边界

- 核心观测每 30 秒更新，业务分析每 60 秒更新；页面隐藏时暂停相应轮询。
- 刷新失败时保留同一筛选范围的上次快照并标记失败，不回退成另一个站点或另一个时间窗口的数据。
- 业务分析单独展示服务端快照生成时间。缓存时间不等于浏览器读取时间。
- “历史覆盖不足”时不展示可信的升降对比。即使有最早请求时间，也不代表采集链路从未中断，应同时看写入失败与覆盖说明。
- 当前观测针对经过公共 HTTP 代理链路的请求；WebSocket 升级链路的覆盖情况以页面观测说明为准。
- 请求结果异步保存，短暂的待写入数量和失败计数用于暴露采集链路状态；在途数量属于当前服务进程。
- 当前精确分位数查询设置了 50,000 行扫描保护（请求结果包含前一对比周期）。超过保护上限会明确提示缩短窗口，不截断样本后继续显示统计。
- 金额是代理记录或估算的消耗，不是上游账单。旧聚合历史可能包含旧估算口径，不能因为新版本调整就视为已按新规则重算。

## 排障示例

**无通道失败：** 请求总数增长、失败数增长、上游尝试为零。先检查路由与模型匹配、凭证及冷却情况，而不是判断上游刚发生了一次 503。

**重试掩盖故障：** 请求成功率较高，但失败尝试和重试挽回同时增长。用户暂时得到结果，某个上游可能正在退化，应从失败站点的尝试日志定位。

**无流量：** 请求与延迟样本为空时显示未知/无样本。它不等同于 100% 可用，也不等同于离线。

**慢请求：** 先看同一窗口的 P95 和最大值，再查看有效样本数。不要用不同模型、不同窗口的平均时长判断单个上游性能。

## 开发验证

新增统计规则应同时验证零样本、无通道 503、429/529、重试成功、流式中断、并发请求隔离、有效样本权重、同名站点与时间范围筛选。数据库测试使用独立的内存库或临时目录。

请求结果表变更需要同步 Drizzle schema、SQLite 迁移与生成的跨数据库契约。修改公共链路后运行类型检查、相关测试、构建和 `npm run repo:drift-check`。
